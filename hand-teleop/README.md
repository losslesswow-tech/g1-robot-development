## 已有功能

- 左右手分别编辑、分别保存姿态；一次只允许一只手进入实物联动。
- 点击三维指节，上下拖动调整对应通道；空白处拖动旋转视角，滚轮缩放。
- 四指各一路弯曲控制，拇指弯曲、旋转各一路，共六路；指节按配置比例联动。
- 滑条和数值框微调模型角度，同时显示实际将使用的原始位置值。
- 导入/导出姿态 JSON；导入只改变编辑姿态，不开启或发送实物动作。
- 实测位置以金色线框叠加，并显示读数时间。超出映射范围时不渲染该实测姿态，原始读数仍显示。
- 默认纯离线模式；只读模式支持连接设备而不写入；实物模式需要已核实的映射和显式开启。

## 角度标定是实物同步的剩余工作

2026-10-12 的初始外观按两张左手照片对齐；右手沿用同一外观依据，是因为用户确认
两手姿态相同。模型显示四指握合、拇指沿掌侧较直伸展。左右手仍分别使用各自的原始读数。
`web/visual-reference.mjs` 仅调整未标定模型的拇指显示零点、基座位置和静态朝向，
不修改角度映射文件、原始位置、仓库驱动或写入值。后续已核实的映射会取代这项显示参考。
拇指的示意弯曲统一朝掌侧（模型 +Z），鼠标拖动也沿用该显示方向；这项方向修正
只作用于未标定模型，不表示已经验证实物拇指的控制极性。
另按用户提供的两张人手参考图，将未标定拇指的旋转显示改为基座绕掌面法向 +Z 摆动：
侧向展开到与四指同向并拢，不再绕伸直拇指自身的长轴旋转。此处同样只是示意几何，
不修改现场角度标定或实物写值。
未标定时滑条和数值框显示 0–1000 原始位置，不将示意角度标作实测角度。
照片不能确定精确关节角、旋转轴或全行程方向，其他位置仍为示意，不能视为同步验收。

`calibration.example.json` 的所有 `verified` 均为 `false`。示例角度只是帮助操作三维图形，
不表示 RH56DFTP 的厂家绝对角度或已测实物角度。前五路示例采用高原始值对应伸直，
拇指旋转单独映射；它们均不是实物动作配置。不得仅把布尔字段改为 true 代替标定。

按已授权的单手、单通道小幅测试收集各通道对应点，另外核对拇指的真实转轴。
标定依据须记录手侧、原始目标、实际读数、观察/测量的关节角和对应证据文件。
建议包含中间点以识别非线性，不直接测试尚未核实的全行程端点。

- `points`：模型关节角 `degrees` 与原始寄存器目标 `raw` 的对应点。角度按升序排列；
  原始值须单调。浏览器逐段线性插值，最终取整数，并同时显示结果。
- 角度零点采用图形关节的参考姿态；四指为相对掌部的弯曲，拇指两路分别定义。
  不能把厂家手册的绝对夹角直接套入这个相对角度坐标。
- `model`：可以调整三维转轴、拇指基座朝向和被动指节联动比例。图形尺寸为示意单位，
  不提供距离测量、碰撞判定或动力学仿真。
- `evidence`：每个通道填写标定依据。左右手分别核实，不自动共享标定结果。
- `model_axes_verified`：确认当前示意转轴、镜像和指节联动与这一只实物相符。
- `verified`：该手的映射和模型核实后才设为 true，并保存到新的现场配置文件。

配置只限定已标定范围，越界拒绝，不能静默截断成其他目标。姿态文件带映射摘要，
避免使用不同标定文件时误读角度含义。首次开启联动只读取并采用当前实测位置，
不发送网页中此前编辑的目标。

完成标定并取得现场动作授权后，使用现场配置启动 `--mode live --mapping 现场配置.json`，
再连接读取、勾选现场确认并点击“开启实物联动”。示例配置启动 live 会被拒绝。
未知固件版本不作为本程序新增的写入门槛；关键剩余项是已观察到存在偏差的几何和角度映射。

## 联动行为与边界

### 当前左手食指单步试验

`step_server.py --plan single-step-left-index.json` 是独立的原始位置试验入口，
只允许左手食指 82–200；它不将示例映射改为已标定，也不开放全手角度联动。
网页先连接读取、勾选现场确认、点击“准备单步控制”，再调整食指模型或滑条，
最后点击“发送一次食指目标”。编辑本身不发送，每次发送后会话都关闭。
未到位时不自动重试，仍按原版六路误差均小于 8 判断整手到位。

其余五路锁定为计划中记录的设备目标 `[2,4,44,*,1,978]`，
准备和发送前均重新读取目标寄存器核对。不会用拇指反馈 963 替换保存的目标 978。
其他目标发生变化、实测位置偏离已观察姿态、越界或并发时均拒绝写入。
底层仍调用仓库原版六路 `set_angles()`，并非独立单寄存器写入；锁定目标不等于机械锁定。
该试验只核实食指运动方向，模型角度仍为示意，其余通道尚未完成标定。

原版接口逐次等待到位，未改成高速伺服流。编辑图形即时响应，实物发送在拖动暂停后触发；
上一目标返回前，只在浏览器保留最新编辑，不在服务端堆积动作。等待可能持续约 8 秒，
外层最长等 22 秒。原版每次读写本身仍有网络超时，因此不能把本版本描述为低延迟连续跟手。

到位仍按原版标准：六路误差均小于 8。已知某些通道目标 1000 时会反馈约 987，
即使视觉上已伸直也不满足这个标准。本程序将关闭后续发送，不能偷偷放宽到位判定。
超时、设备错误或未到位后不自动补发，不自动回退，也不自动恢复联动。

控制会话每 2 秒维持一次，6 秒无维持则拒绝后续动作。切走页面、关闭页面或点击关闭联动
会清除待发目标。已提交给实物的目标可能继续执行；关闭联动、退出程序、断网或杀掉等待进程
都不等于停止电机。界面没有虚构的独立急停或卸力指令。

本程序同一宿主机的 live 实例有进程锁，同一实例只有一个写入会话。
这个锁不能排斥厂家工具、原仓库 CLI 或其他宿主机；现场仍须保证只有一个控制来源。
服务面向受信任的局域网，默认只监听本机，不提供公网部署。
