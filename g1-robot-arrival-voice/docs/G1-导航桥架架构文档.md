# 宇树 G1 机器人导航 + 桥架控制架构文档

> 本文档记录宇树 G1 人形机器人接入 ROS1 导航容器、通过桥架容器做 DDS↔ROS1 控制的完整过程，供其他智能体/工程师复制部署。

## 1. 网络拓扑与设备清单

| IP | 设备 | 说明 |
|---|---|---|
| `192.0.2.16` | 导航宿主机 | 有线网卡 `enp4s0`，跑两个 Docker 容器 |
| `192.0.2.8` | G1 上位机（NVIDIA Jetson aarch64） | SSH `operator@` / 密码 `123`，跑 ROS foxy+noetic、unitree_sdk2 |

## 2. 架构总览

```text
┌─────────────────────────┐        ┌──────────────────────────┐
│ 导航容器 robot-navigation     │        │ 桥架容器 g1-bridge        │
│ (ROS1 noetic, host 网络) │        │ (ROS1 noetic, host 网络)  │

│ SLAM / 建图 / 规划 / 避障│        │ g1_ros1_sdk_node         │
│ 传感器(MID360)           │        │   unitree_sdk2           │
│                         │        │   LocoClient (G1 硬件)    │

└─────────────────────────┘        └──────────┬───────────────┘

                                     └───────────────────┘
```

两个容器都用 `--network host`，共享宿主机 `roscore`（`127.0.0.1:11311`）。

## 3. 导航容器配置修改

文件：`/home/operator/nav_map/x_nav.yaml`（挂载到容器的 `/nav_map`）

改动两处（改前先备份）：

```yaml
# ① robot 段网卡名：enp2s0 → enp4s0
robot:
  sub_cmd_vel_topic: /cmd_vel
  networkInterface: enp4s0

# ② x_nav 段机器人型号：GO2_EDU → G1_BRIDGE
x_nav:
  ...
  robot_model: G1_BRIDGE   # 不匹配内置分支，导航容器不自己跑机器人控制节点
```

**为什么用 `G1_BRIDGE` 而不是 `G1`**：`robot_web_controller.py` 里 `robot_model == "G1"` 会执行 `rosrun g1_ros1_sdk g1_ros1_sdk`（该包在导航容器里不存在）。用 `G1_BRIDGE` 不命中任何分支，导航容器只跑 SLAM/规划/传感器，机器人控制交给桥架容器，避免双节点竞争 `/cmd_vel`。

```cmake
add_executable(g1_ros1_sdk src/g1_ros1_sdk.cpp)

  ${catkin_LIBRARIES} unitree_sdk2 ddsc ddscxx fmt rt pthread
)

add_executable(g1_control src/g1_control.cpp)
target_link_libraries(g1_control
  ${catkin_LIBRARIES} unitree_sdk2 ddsc ddscxx fmt rt pthread
)
```

> ⚠️ **三个编译坑**（都踩过）：
> 1. **不能加 `-I/usr/local/include/dds`**：`dds/features.h` 会与系统 glibc `features.h` 冲突，导致 `__GLIBC_PREREQ` 未定义报 `missing binary operator before token "("`。正确做法是加 `-I/usr/local/include`，让 `#include "dds/..."` 能解析、`#include <features.h>` 走系统路径。
> 2. **必须链接 `fmt`**：unitree_sdk2 依赖 fmt 格式库，不链会 `undefined reference to fmt::v8::...`。
> 3. **必须有 package.xml**：没有它 catkin 不识别包，`catkin_make` 静默跳过编译。

#### pkg/src/g1_ros1_sdk.cpp（常驻节点）

```cpp
// G1 ROS1 SDK — bridge Unitree G1 LocoClient (DDS) to ROS1 topics.
#include <ros/ros.h>
#include <sensor_msgs/Imu.h>
#include <geometry_msgs/Twist.h>
#include <unitree/robot/g1/loco/g1_loco_client.hpp>
#include <unitree/dds_wrapper/robots/g1/g1_sub.h>
#include <thread>
#include <chrono>

unitree::robot::g1::LocoClient* g_loco = nullptr;
ros::Publisher g_imu_pub;

void LowStateHandler(const void* msg) {
  const unitree_hg::msg::dds_::LowState_* low =
      static_cast<const unitree_hg::msg::dds_::LowState_*>(msg);
  if (!low) return;
  sensor_msgs::Imu imu;
  imu.header.frame_id = "imu_link";
  imu.header.stamp = ros::Time::now();
  const auto& q = low->imu_state().quaternion();
  const auto& gyro = low->imu_state().gyroscope();
  const auto& acc = low->imu_state().accelerometer();
  imu.orientation.w = q[0]; imu.orientation.x = q[1];
  imu.orientation.y = q[2]; imu.orientation.z = q[3];
  imu.angular_velocity.x = gyro[0];
  imu.angular_velocity.y = gyro[1];
  imu.angular_velocity.z = gyro[2];
  imu.linear_acceleration.x = acc[0];
  imu.linear_acceleration.y = acc[1];
  imu.linear_acceleration.z = acc[2];
  g_imu_pub.publish(imu);
}

void CmdVelCallback(const geometry_msgs::Twist::ConstPtr& msg) {
  if (!g_loco) return;
  int cmd = static_cast<int>(msg->linear.z);
  if (cmd == 1) { g_loco->BalanceStand(); return; }
  else if (cmd == 2) { g_loco->Damp(); return; }
  g_loco->Move(msg->linear.x, msg->linear.y, msg->angular.z);
}

int main(int argc, char** argv) {
  ros::init(argc, argv, "g1_ros1_sdk_node");
  ros::NodeHandle nh;
  ros::NodeHandle pnh("~");
  std::string net_if;
  pnh.param<std::string>("networkInterface", net_if, "enp4s0");
  ROS_INFO("g1_ros1_sdk: network interface = %s", net_if.c_str());

  unitree::robot::ChannelFactory::Instance()->Init(0, net_if);

  unitree::robot::g1::LocoClient client;
  client.Init();
  client.SetTimeout(10.0f);
  client.SwitchMoveMode(true);
  g_loco = &client;

  unitree::robot::ChannelSubscriberPtr<unitree_hg::msg::dds_::LowState_> lowstate_sub;
  lowstate_sub.reset(new unitree::robot::ChannelSubscriber<unitree_hg::msg::dds_::LowState_>("rt/lowstate"));
  lowstate_sub->InitChannel(LowStateHandler, 1);

  g_imu_pub = nh.advertise<sensor_msgs::Imu>("/sdk/imu", 50);
  ros::Subscriber cmd_sub = nh.subscribe<geometry_msgs::Twist>("/cmd_vel", 100, CmdVelCallback);

  ROS_INFO("g1_ros1_sdk: standing up...");
  client.StandUp();
  std::this_thread::sleep_for(std::chrono::seconds(3));
  client.Start();
  ROS_INFO("g1_ros1_sdk: ready");

  ros::Rate rate(100);
  while (ros::ok()) { ros::spinOnce(); rate.sleep(); }
  client.Damp();
  return 0;
}
```

> ⚠️ **坑**：ROS 私有参数不能用 `nh.param("~name")`（会抛 `InvalidNameException`），必须用 `ros::NodeHandle pnh("~")` 再 `pnh.param("name")`。

#### pkg/src/g1_control.cpp（控制 CLI）

```cpp
// G1 control CLI — 一次性控制命令
#include <iostream>
#include <string>
#include <thread>
#include <chrono>
#include <unitree/robot/g1/loco/g1_loco_client.hpp>

int main(int argc, char** argv) {
  if (argc < 3) {
    std::cerr << "用法: g1_control <networkInterface> <command> [args...]" << std::endl;
    std::cerr << "命令: stand | start | damp | stop | balance | move <vx> <vy> <vyaw> | query" << std::endl;
    return 1;
  }
  std::string net_if = argv[1], cmd = argv[2];
  unitree::robot::ChannelFactory::Instance()->Init(0, net_if);
  unitree::robot::g1::LocoClient client;
  client.Init();
  client.SetTimeout(10.0f);

  if (cmd == "stand")      { client.StandUp(); }
  else if (cmd == "damp")  { client.Damp(); }
  else if (cmd == "stop")  { client.StopMove(); }
  else if (cmd == "balance") { client.BalanceStand(); }
  else if (cmd == "start")   { client.Start(); }
  else if (cmd == "move") {
    float vx = std::stof(argv[3]), vy = std::stof(argv[4]), vyaw = std::stof(argv[5]);
    client.Move(vx, vy, vyaw);
  } else if (cmd == "query") {
    int fsm_id = -1, fsm_mode = -1;
    client.GetFsmId(fsm_id);
    client.GetFsmMode(fsm_mode);
    std::cout << "G1 FSM: fsm_id=" << fsm_id << " fsm_mode=" << fsm_mode << std::endl;
  } else { std::cerr << "未知命令: " << cmd << std::endl; return 1; }
  std::this_thread::sleep_for(std::chrono::seconds(1));
  return 0;
}
```

## 6. G1 状态机（LocoClient fsm_id）

| fsm_id | 状态 | 对应 API |
|---|---|---|
| 0 | 零力矩 ZeroTorque | `ZeroTorque()` |
| 1 | 阻尼 Damp（卸力，收工用） | `Damp()` |
| 2 | 蹲下 Squat | `Squat()` |
| 3 | 坐 Sit | `Sit()` |
| 4 | 站立 StandUp | `StandUp()` |
| 500 | 行走模式 Start | `Start()` |

速度控制：`Move(vx, vy, vyaw)` / `SetVelocity(vx, vy, omega, duration)` / `StopMove()`。

**启动时序**（桥架节点内置）：`StandUp()` → 等 3 秒 → `Start()` → 进入待命，等 `/cmd_vel`。

**FSM 切换实测规则（2026-08-31）**：

| 转换 | 是否允许 | 备注 |
|---|---|---|
| 0 → 1 → 4 → 500 | ✅ | 标准上升路径 |
| 500 → 1 | ✅ | 行走模式唯一可直接退出的状态 |
| 500 → 4 / 500 → 0 | ❌ | MCU 拒绝（`SetFsmId` 无效），必须先 `damp` 回 1 |
| 4 → 0 | ❌ | 需经阻尼中转 |

> 收工路径：`500 → damp(1)`（或 `0 → damp(1)`）→ 断电/`stand`。
> ⚠️ 网线断开时 DDS 连不上 MCU（`does not match an available interface` / domain 创建失败），所有 `g1_control`/`g1_arm` 命令不可用——机器人断电即卸力，无需命令。

## 7. 完整坑点清单（务必规避）

1. **docker cp 目标路径**：用 `/home` 下绝对路径，`/tmp` 被 snap docker 沙箱拒绝。
2. **dds/features.h 冲突**：不能 `-I/usr/local/include/dds`，用 `-I/usr/local/include`。
3. **缺 fmt 链接**：unitree_sdk2 依赖 fmt，必须 `-lfmt`。
4. **缺 package.xml**：catkin 静默跳过编译，表现是 make 秒完成、无产物。
5. **package.xml 邮箱格式**：`dsh@localhost` 非法，需 `developer@example.invalid`。
6. **ROS 私有参数**：用 `NodeHandle pnh("~")`，不能 `nh.param("~name")`。
7. **网卡名必须匹配**：宿主机实际网卡是 `enp4s0`，配置里写 `enp2s0` 会 `does not match an available interface`。
8. **robot_model 用 G1_BRIDGE**：避免导航容器和桥架容器双节点竞争 `/cmd_vel`。
9. **arm action 必须 SetTimeout(10s)**：G1ArmActionClient 默认超时太短，首次 DDS 服务调用报 `3104 Call api timeout`，误判服务不可用；`GetActionList` 可验证服务真实存在。
10. **G1 挥手用 arm action 服务**：LocoClient 的 `WaveHand`/`SetTaskId(0/1)` 在 G1 固件上不触发挥手；正确通道是 `G1ArmActionClient::ExecuteAction`（真实动作表见 5.4 节）。
11. **灵巧手 Modbus 写后必须读 ACK**：Inspire 手每次写寄存器后不读 12 字节 ACK，发送缓冲满 → TCP 流控 → 手停止响应（`inspire_hand_ctl.py` 已处理）。
12. **手臂低级控制方向**：G1 肩 Pitch **+ 方向为后摆**（probe 实测，会导致上身后仰），前伸用 `-90°`。
13. **灵巧手角度方向**：Inspire 手 **1000=伸开、0=闭合**（实测，与直觉相反）。

## 8. 关键安全提醒

- G1 是真实人形机器人，`StandUp`/`Start`/`Move` 都会让机器人实际运动。
- 首次部署务必确认：周围无障碍、有人监护、或机器人已吊挂/支架固定。
- 桥架节点的 `g1_start.sh` 默认「自动站立+启动」，如不想自动站立，注释掉 `g1_ros1_sdk.cpp` 里的 `StandUp()`/`Start()` 调用。

## 9. 雷达驱动配置修复记录（2026-08-31）

**症状**：livox 节点 `/livox_lidar_publisher` 存活但 `/livox/lidar`、`/livox/imu` 无发布者（`Publishers: None`）。

**根因**：`robot_web_controller.py` 用裸命令启动 livox：
```python
cmd = ["rosrun", "livox_ros_driver2", "livox_ros_driver2_node"]
```
`user_config_path` 参数为空 → `LdsLidar::InitLdsLidar("")` → `ParseCfgFile("")` fopen 失败 → `Init lds lidar failed!`，节点存活但不发布。容器重启后 rosmaster 参数丢失（之前靠 `rosparam set /livox_lidar_publisher/user_config_path` 临时设置，不持久）。

**修复**（导航容器内，已应用）：
```python
# /catkin_ws/src/x_nav_control/scripts/robot_web_controller.py 第 209 行
cmd = ["rosrun", "livox_ros_driver2", "livox_ros_driver2_node",
       "_user_config_path:=/nav_map/MID360_config.json"]
```
`/nav_map/MID360_config.json`（宿主机 `/home/operator/nav_map/`，已挂载）内容：host `192.0.2.16`，lidar `192.0.2.14`。

> ⚠️ **容器重建（docker rm）会丢失此补丁**（改动在镜像层）。重建后需重新执行：
> ```bash
> docker exec robot-navigation bash -lc 'F=/catkin_ws/src/x_nav_control/scripts/robot_web_controller.py; \
>   sed -i "s/livox_ros_driver2_node\"]/livox_ros_driver2_node\", \"_user_config_path:=\/nav_map\/MID360_config.json\"]/" $F'
> docker restart robot-navigation
> ```
> 或 `docker commit robot-navigation` 固化镜像。

**验证结果**（2026-08-31）：
- `/livox/lidar`：10 Hz，20064 点/帧，frame_id=`lidar_link`，雷达 SN `47MDN6L0030383`
- `/livox/imu`：~203 Hz
- `/sdk/imu`（G1 机身）：~1010 Hz

**联动注意事项**：重启 `robot-navigation` 容器 = rosmaster 重启 → `g1-bridge` 容器内的 `g1_ros1_sdk_node` 失联且**不会自动重连**，`/sdk/imu` 会停。恢复方式：`docker restart g1-bridge`（会重新执行 StandUp→Start，机器人有站立动作，注意安全）。

**x_slam / x_planner**：由 robot_web_controller 的守护启动，但**建图/定位需通过 Web 界面（8000 端口）操作触发**，非容器重启自动拉起。

### 9.1 G1 断电重启后的雷达恢复（2026-08-31 实测）

**症状**：G1 整机断电再开机后，雷达 `.120` 能 ping 通，`/livox_lidar_publisher` 节点也活着，但 `/livox/lidar`、`/livox/imu` 长时间无新消息（`rostopic hz` 显示 `no new messages`）。

**根因**：雷达驱动进程从容器启动起一直存活，**跨过了 G1 断电**；雷达重新上电后，驱动没有和它重新握手，处于「节点存活但收不到数据」的假活状态。`robot_web_controller` 的 auto_check 只检查进程死活（`poll()`），不检查数据流，所以不会自动恢复。

**恢复（无需重启容器，无机器人动作）**：只杀掉雷达驱动进程，进程管理器会在 ~1 秒内用正确命令自动拉起，驱动重新和雷达握手后数据即恢复。

```bash
docker exec robot-navigation bash -c 'kill $(pgrep -f livox_ros_driver2_node)'
sleep 3
docker exec robot-navigation bash -c 'source /opt/ros/noetic/setup.bash; rostopic hz /livox/lidar'  # 期望 ~10 Hz
```

**判据**：`/livox/imu` 的 `linear_acceleration.z`——原始倒装时 ≈ **−1.0**（重力落 −Z）；2026-08-31 做完翻转后现在 ≈ **+1.0**（见 9.2 节）。

### 9.2 G1 雷达倒装翻转 + 几何适配（2026-08-31 完成）

**背景**：G1 头部 MID360 是**倒装**的（官方 URDF `g1_29dof_rev_1_0.urdf` 的 `mid360_joint` rpy=`[π, 0.051, 0]`，roll=180°）。原版 `livox_ros_driver2` 只把 `extrinsic_parameter` 应用到点云、不应用到 IMU，导致点云和 IMU 朝向矛盾（点云翻正、IMU 重力仍 −1g），SLAM 建图上下颠倒。

**改法（照 deepglint 对 G1 的成熟方案）**：

1. 驱动补丁（让 extrinsic 同时作用于 IMU）——改 `pub_handler.{h,cpp}`：
   - `PubHandler` 加 `static ExtParameterDetailed extrinsic_`
   - IMU 回调里把 `extrinsic_.rotation` 应用到 gyro 和 acc
   - `SetLidarsExtParam` 改为返回 `ExtParameterDetailed`，调用点赋值给静态 `extrinsic_`
2. 重新编译：
   ```bash
   docker exec robot-navigation bash -lc 'source /opt/ros/noetic/setup.bash && cd /catkin_ws && catkin_make --pkg livox_ros_driver2'
   ```
   ⚠️ 备份目录不能放 `/catkin_ws/src/` 里（catkin 按 package.xml 重名会报冲突）。
3. 配置 `/nav_map/MID360_config.json`：`extrinsic_parameter.roll: 0 → 180`
4. 重启驱动：`kill $(pgrep -f livox_ros_driver2_node)`，auto_check 自动拉起
5. 判据：`/livox/imu` 的 `linear_acceleration.z` 从 −1g → **+1g**

**几何参数**（`x_nav.yaml`，按官方 URDF 关节链推导）：

| 参数 | GO2 原值 | G1 值 | 依据 |
|---|---|---|---|
| `base_link_hight` | 0.5 | 0.78 | 骨盆离地（腿链 Z 累加 ≈0.75 + 脚底） |
| `imu_link_to_base_link_Trans` | [0.2, 0, 0] | [0, 0, 0.47] | MID360 离地 ≈1.25m，高于骨盆 0.47m |
| `imu_link_to_base_link_rpy` | [0,0,0] | [0,0,0] | 驱动已翻转 IMU，保持单位阵 |

**⚠️ 改 x_nav.yaml 后要「重载 + 重启」两步**（只重启 x_slam 不够，它读的是参数服务器旧值）：

```bash
# ① 重载进参数服务器（x_nav.yaml 只在 robot_web_controller.py 启动时一次性 upload_params，之后不读文件）
docker exec robot-navigation bash -lc 'source /opt/ros/noetic/setup.bash; rosparam load /nav_map/x_nav.yaml'
# ② 重启 x_slam（mapping 命令示例，目录以 Web 实际为准）
docker exec robot-navigation bash -c 'kill $(pgrep -f "/nav/x_slam"); sleep 2; \
  source /opt/ros/noetic/setup.bash; export ROS_MASTER_URI=http://localhost:11311; \
  cd /; nohup /nav/x_slam mapping /nav_map/999 > /tmp/x_slam_restart.log 2>&1 &'
```

**备份**：驱动源码 `/catkin_ws/livox_ros_driver2.bak_20260831_043942`，配置 `/nav_map/MID360_config.json.bak2_*`，`x_nav.yaml` 有 `.bak`/`.g1bak` 可回退。

## 10. 灵巧手控制（Inspire RH56DFTP ×2）

G1 上两只 Inspire 灵巧手（以太网版，RH56DFTP），通过网线接入 192.0.2 网段，**Modbus TCP** 协议。

| 手 | IP | 端口 |
|---|---|---|
| 左手 | `192.0.2.3` | 6000 |
| 右手 | `192.0.2.4` | 6000 |

**寄存器**（每手 6 自由度：小指/无名指/中指/食指/拇指弯/拇指旋，值 0..1000）：

| 寄存器 | 地址 | 功能 |
|---|---|---|
| `ANGLE_SET` | 1486 | 写目标角度（FC=0x10） |
| `SPEED_SET` | 1522 | 写电机速度（FC=0x10） |
| `ANGLE_ACT` | 1546 | 读实际角度（FC=0x03） |
| `FORCE_ACT` | 1582 | 读抓取力（FC=0x03） |
| 触觉传感器 | 3000-5011 | 17 区：每指 tip(3×3)/nail(12×8)/pad(10×8) + 拇指 + 手掌(8×14)，每格 0..4095 |

**控制脚本**：`/home/operator/robot-project/inspire_hand_ctl.py`

```bash
python3 inspire_hand_ctl.py status              # 读两只手角度+力
python3 inspire_hand_ctl.py open   R 15         # 右手张开到 15%
python3 inspire_hand_ctl.py close  L            # 左手闭合(100%)
python3 inspire_hand_ctl.py grip   B 50         # 双手到 50%
python3 inspire_hand_ctl.py pos    R 100 200 300 400 500 600  # 精确 6 角
python3 inspire_hand_ctl.py finger R 0 800      # 单指(小指)到 800
python3 inspire_hand_ctl.py speed  R 300        # 速度 0-1000
```

> ⚠️ **协议坑**：每次写寄存器后**必须读 ACK**（12 字节），否则灵巧手发送缓冲满导致 TCP 流控阻塞、手不再响应；其 Modbus 服务端 TX-ID 有 off-by-one bug，正常忽略。控制脚本已处理。
>
> ⚠️ **安全**：灵巧手动作是真实手指运动，抓取力寄存器 `FORCE_ACT` 实时可读；避免夹住异物。角度 **1000=伸开、0=闭合**（实测，与直觉相反）。

## 11. 手臂低级控制（g1_arm）

通过 `rt/arm_sdk` 发布 `LowCmd_` 直接控制 G1 双臂（7 DOF×2：肩 pitch/roll/yaw + 肘 + 腕 roll/pitch/yaw），weight 机制接管手臂（`motor_cmd[29].q = 1.0`）。

**关节索引**（35 关节数组）：左肩 pitch=15 roll=16 yaw=17 肘=18 腕 roll=19 pitch=20 yaw=21；右肩 pitch=22 roll=23 yaw=24 肘=25 腕 roll=26 pitch=27 yaw=28。

**工具**：`g1_arm`（容器内 `/catkin_ws/devel/lib/g1_ros1_sdk/g1_arm`，源码 `/home/operator/g1bridge/pkg/src/g1_arm.cpp`）

```bash
g1_arm enp4s0 info      # 读当前手臂关节角度 (rad)
g1_arm enp4s0 forward   # 双臂前伸（肩 Pitch -90°，肘伸直）
g1_arm enp4s0 side      # 双臂侧举（肩 roll ±90° 肘 90°）
g1_arm enp4s0 down      # 双臂下垂（全 0）
g1_arm enp4s0 probe     # 肩 pitch 小幅试探方向
```

> ⚠️ **方向坑**：G1 肩 Pitch **+ = 后摆**（实测导致上身后仰），前伸用 **-90°**（rad，`-π/2`）。
> 低层控制适合精确姿态；日常手势（挥手/握手等）优先用 5.4 节的 `action` 预设动作。
