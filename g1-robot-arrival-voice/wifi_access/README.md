## 当前方案与执行边界

先验证机器人上位机作为无线与内部以太网之间的临时路由，而不是立即迁移导航或雷达驱动。保留宿主机原导航地址，避免现在重载 ROS master。此包只用于检查；成功后仍需适配运动桥接的 DDS 单播发现、断线停车及持续连接，再完成受控导航验收。

执行前必须取消导航、终止任务，机器人稳定，有人监护且硬件遥控停止可用。测试期间不要操作导航。启动脚本要求在现场终端输入 `STATIONARY`，因为恢复网络可能恢复现有节点的收发；SSH/sudo 密码仅在现场终端输入，不保存到包或日志。

临时操作：

| 位置 | 操作 |
|---|---|
| 宿主机 | 按 PID、启动时间和可执行文件名核对现有 `g1_ros1_sdk`，临时 SIGSTOP 暂停；不退出进程、不触发其 Damp/StandUp/Start 代码 |
| 宿主机 Wi-Fi | 增加 `192.0.2.6/32` 临时地址 |
| 宿主机 NAT | 在 POSTROUTING 首部增加 6 条唯一标记的 ACCEPT 例外，仅保留 `.123.10 → .123.120/.161/.164` 的 UDP/ICMP 原源地址；不删除已有 MASQUERADE |
| 宿主机 | 仅增加到 `.123.120`、`.123.161`、`.123.164` 的三条 `/32` 路由，经 `.2.83`，源地址 `.123.10` |
| 机器人 | 增加 `.123.10/32 via .2.7 dev wlan0` 返回路由，以及仅针对 `.123.10` 的 `eth0` proxy ARP 项 |
| 机器人防火墙 | 临时增加 8 条带本次唯一标记的 FORWARD 规则，仅允许 `.123.10` 与 `.123.120/.161` 之间、`wlan0 ↔ eth0` 的 UDP/ICMP；`.164` 是机器人本机地址，不经过 FORWARD |

不修改默认网关、现有较宽的路由、防火墙默认策略或已有规则、IP 转发开关、雷达配置或开机服务。已有同名资源、地址不符、有线 IPv4 仍存在、桥接身份不明确、任务未空闲时拒绝应用。执行中失败按日志撤销本次拥有的资源。

第一次现场运行因导航状态为“请重新设置位姿（重定位）”而在宿主机配置之前拒绝；机器人侧已报告 `rolled_back / remaining: []`，未执行 DDS/雷达实机查询。该状态代表定位受阻，不能标为导航空闲；新版仅精确允许这个状态和“导航模式 空闲”，仍要求现场静止确认、无任务、无受管理或暂停的语音任务。前置校验在连接机器人前执行，应用宿主机配置前再次校验。对准中、规划成功、导航进度或未知状态仍拒绝。

现场还确认机器人 `FORWARD` 默认策略为 `DROP`。新版添加上述临时窄范围规则，并读取 FORWARD/DOCKER-USER 原规则用于诊断；不清空规则或修改默认策略。回退按唯一标记和完整匹配删除本次规则；规则状态无法核实时报告 `rollback_incomplete`，仍尝试独立清理返回路由。

两端独立看门狗在 180 秒触发自动回退。正常退出时立即撤销并读取回执；网络资源清理完成后才 SIGCONT 恢复旧桥接。宿主机使用 pidfd 发送信号，PID 被复用时不发信号。清理失败会明确报告 `rollback_incomplete`，并保持旧桥接暂停，需处理后再导航；不得把拔线或撤销路由当作机器人的停车指令。

## 只读检查

`query.cpp` 仅调用 `GetFsmId`、`GetFsmMode` 和订阅 `rt/lowstate`。使用 domain 0、明确选择 `.123.10` 地址、关闭组播并配置 `.123.161/.164` 单播 peers。无速度、模式、站立或卸力调用。`--peers` 严格限制内部 G1 地址和数字端口；`--wired` 用于有线默认发现对照。旧 `--query` 的默认端口探测在本机无效，检查脚本已改用 `--peers`。

`dds_discovery.py` 在检查和会话中使用 `--join-spdp --seconds 35`：通过临时 UDP 套接字在指定 eth0 加入 `239.255.0.1`，接收 35 秒覆盖默认最长 30 秒的周期发现间隔；退出、异常时关闭套接字释放自身成员资格。内核可能发送 IGMP 成员报文，`application_packet_sends=0` 和兼容字段 `packet_sends=0` 仅表示程序没有 send/sendto 调用，不代表链路上没有内核报文。它不创建 DDS participant、不调用运动接口、不保存原始载荷、不加入混杂模式。严格解析 SPDP DATA 的 UDPv4 metatraffic unicast locator，仅接受报文源与 locator 地址相同的 `.161/.164`，最多 64 个。结果经 SSH 取回，校验后作为本次 C++ 明确单播 `IP:PORT`。捕获失败先显示报告，再在临时路由、防火墙应用前退出。无 `--join-spdp` 参数时仍是纯被动接收；接收窗口允许 2–45 秒。

`sensor_probe.py` 观察 10 秒 `/livox/lidar`、`/livox/imu` 和 `/sdk/imu` 的非 latched 新消息，并记录 `/cmd_vel` 是否存在非零输出。旧运动桥接检查期间被暂停，因此它原先发布的 `/sdk/imu` 可以为零；直接 DDS 检查的 `lowstate_samples` 用于验证机器人状态数据。雷达节点若没有恢复数据，需要另行诊断，不能用节点存活代替数据可用。

`start_check.sh --lidar-unicast-trial` 是独立选择的限时检查：沿用原网络保护和旧桥接暂停，网络生效且完成只读 DDS 查询后，仅通过原进程管理 API 重载 `sensor_node`。`livox_trial.py` 校验原/候选哈希、单一雷达配置、无线 /32 别名和原驱动身份；候选进程启动后立即恢复原可执行文件，清理时恢复原驱动进程，另有 75 秒独立看门狗。不会重载 Web、SLAM、规划器或运动桥接，不切换机器人 FSM，也不发运动 API；雷达初始化仍使用现有雷达配置。回退确认包含原二进制哈希、原驱动新 PID 和该次日志事件。

现场检查期间机器人须静止、导航/任务停止、有人监护且遥控停止可用。若只收到 SSH 成功或 DDS 成功、没有 ROS 点云/IMU 新消息，仍判定未通过。若没有 `sensor_rolled_back`（或幂等 `sensor_already_rolled_back`）及两端网络回退回执，保持导航停止并检查日志。候选方案未安装为持久服务，有线原驱动及其配置保留。

用户因机器人电量不足要求继续离线准备。完整候选方案见 `../network_modes/README.md`。本模块新增 `--session-lease` 为候选无线会话提供 root 独立回退看门狗：要求旧桥接已停止、sudo 调用者拥有的 0600 普通心跳文件、单一硬链接，最初 180 秒安装宽限后需 30 秒内的新心跳，硬上限 1 小时。默认限时只读检查不启用此选项，仍保持原先 180 秒回退行为。

租约仅管理本次网络资源，不充当机器人急停。候选桥接单独管理有限时长速度、状态超时锁定和 15 秒主控心跳退出；新会话不会暂停/恢复或杀掉旧桥接。旧程序的现场交接及新桥接的停止行为仍需开机后受监护验收。
