# 现有导航协议下的保守自动播报

用户已明确接受：旧协议没有导航任务 ID，跨任务迟到结果无法绝对排除误关联。此接入独立于 `core.py` 的严格任务 ID 消费者；本地生成的 UUID 只用于提交去重，不能证明规划器结果的归属。

2026-10-09 在地图 1009 手动导航“2”点的只读记录确认：

| 信号 | 真实发布节点 | 用途 |
| --- | --- | --- |
| `/x_nav/state` 的 `14` | `/x_planner` | 建立新候选，不表示到达 |
| `/x_nav/goal_path` 的路径终点，坐标系 `map` | `/x_planner` | 在开始前后 2 秒内与当前地图已保存点位唯一匹配 |
| `1#进度#总数` 或 `12` | `/w_nav` | 本轮已执行导航的证据 |
| `13` | `/w_nav`，已实际观测 | 唯一允许提交播报的完成信号 |

目标匹配使用平面 XY 误差不超过 3 cm、朝向 yaw 差不超过 0.10 rad，且必须唯一。现场确认规划器会将终点高度投影到地面：原点保存高度为 0，路径终点高度约 -0.484 m，因此不能用 Z 或完整 roll/pitch 四元数匹配身份。它仅用于识别规划器的目标，**不会用机器人当前位置、距离、停止或 `12` 推断到达**。无法唯一匹配的点位不播报，其他地图/导航模式需要先校准。

收到 `13` 后至少等待 0.5 秒，并取得完成消息之后的一次元数据复核，期间取消或失败仍可作废候选。监听 `/planner/cmd` 的取消/暂停/重规划，以及 `/node_cmd` 的导航模式切换。失败、目标变化、切图、点位文件变更、网页配置变更、ROS 发布节点地址变化、断线、重启、队列积压、过期均作废候选。暂停后恢复需要一次新的规划成功，宁可漏播。候选超过 300 秒过期。

SQLite 在音频提交前持久化占位；重复到达不重复提交。音频忙、未配置点位、超时或失败直接跳过，不排队补播、不自动重试。音频提交以后不能撤回已发送给机器人的 TTS/WAV 请求；网页“暂停自动播报”只阻止后续触发。

## 启动

音频网页仍在导航宿主机运行，通过其原有 `UnitreePlayer` 和 SSH 会话使用机器人音频。监听器运行在已有 `nav_robot` 容器的独立目录，不安装 SDK、不启动导航、不发布 ROS 消息、不重启容器或桥接。

网页默认暂停自动播报。启动监听器后可在页面看到连接状态、地图、当前候选点位及上次提交结果。先保存地图名和点名完全匹配的播报内容，例如 `1009 / 2`。选择“启用自动播报”后，**从下一次新导航开始**；启动或启用时已经完成/进行中的导航不会补播。网页重启后再次默认暂停。

新增、移动或重命名导航点后，必须先在原导航页面执行“保存点位”，确认当前地图目录的 `nav_points.txt` 已包含更新，再开始导航。规划器内存里的点位列表可以先于文件更新；本监听器读取已保存文件，内存里可导航但文件里没有的点位会匹配失败并跳过播报。保存文件会作废当前候选，需要重新开始导航，过去跳过的到达不会补播。语音配置中的点名必须是导航点名称，不能仅凭界面行号推断。

容器中启动监听器（路径按部署位置调整）：

```bash
source /opt/ros/noetic/setup.bash
cd /opt/g1-arrival-voice/current
python3 -m arrival_voice.legacy_auto --database /opt/g1-arrival-voice/state/legacy.sqlite3 --log /opt/g1-arrival-voice/state/legacy.jsonl --allow-legacy-auto --allow-robot-audio
```

不带两个 `--allow` 参数时只记录，不提交音频。每台机器人只运行一个监听器，锁防止同一数据库被重复消费。保留数据库，不清空它来恢复播报。容器替换前备份独立状态目录；这里没有配置自启动。

## 现场验证边界

短中文 TTS 和预录 WAV 的独立实机播放均已由用户确认听到。2026-10-09 这轮导航中机器人停在“2”点附近，原导航页面起初没有显示到达，记录持续为 `12`。之后 `/w_nav` 实际发出 `13`，距第二次 `14` 约 993.9 秒，随后空闲。这确认了完成消息的来源，但本轮为只读记录，不是自动播报验收；该长时候选也超过默认 300 秒时限，保守模式将跳过，不补播。

本地测试覆盖目标匹配、对准不播报、裸结果拒绝、重复去重、取消/失败/切图/断线/重启/过期拒绝、音频开关和配置检查。后续用户自行切换到 FSM 501 后，地图 `1009/2` 已取得真实 `13`，自动提交一次 TTS，用户明确确认听到；详见 [实机验收记录](HARDWARE_TEST_20261009.md)。不要向真实 ROS 导航话题注入伪造完成消息测试。

59 项测试在本地 Python 3.9.13 和导航容器 Python 3.8.10 均通过。独立 Edge 模拟页面验证了自动开关、状态提示、复用已保存内容提交模拟播报和手机布局，没有连接机器人音频。真实 ROS 只读集成检查确认地图 1009、监听连接成功、自动开关默认关闭；元数据查询在后台执行，现有状态接口的一秒 CPU 采样不阻塞导航事件消费。
