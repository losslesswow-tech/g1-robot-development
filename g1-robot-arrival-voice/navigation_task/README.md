在原导航任务编辑器中添加“语音播报”步骤，放在导航步骤之后。可以输入文字、导入预录 WAV，或选择已保存播报内容。例如：导航到地图 1009 的 2 点 → 语音播报 → 导航到 3 点 → 语音播报。地图切换仍使用原任务步骤；目标点必须先在原导航页面保存。

现场入口：[导航任务页面](http://192.0.2.5:8000/app/rviz.html?g1-task=20261010)。进入“任务选择 → 新建任务 → 任务流程”，动作下拉框首项为“语音播报”。旧标签页可能保留旧 HTML/脚本缓存，请打开此带版本参数的入口并按 Ctrl+F5。音频编辑器的 18768 端口是另一页面，任务控件位于原导航前端的 8000 端口。

文字上限 1000 字。导入音频沿用现有服务要求：16 kHz、单声道、16 位 PCM WAV，最多 10 MB。文字语音接口返回的是“提交成功”，任务右侧的等待秒数应留出播报时间。WAV 接口等待音频流播放结束。已保存播报在执行步骤时按地图名和点名读取，删除或修改引用会影响之后的任务执行。

含语音的任务要求本次新规划、保存点位匹配、导航执行证据和真实 `13` 到达消息。暂停、取消、规划失败、点位文件变化或目标不匹配会使到达核验失效；恢复导航步骤会重新规划。不能用机器人停止或状态 `12` 代替到达成功。旧协议仍没有任务 ID，跨任务迟到结果不能绝对排除误关联。

每个任务运行、循环和步骤只提交一次语音；结果不确定时停止任务，不自动重试。已经提交给机器人的语音无法靠暂停撤回。含语音的任务由任务步骤接管播报，独立到达监听会抑制同次点位播报，避免重复。该接管不受独立自动播报开关控制。

## 文件与部署

- `arrival_voice/task_voice.py`：任务语音、音频导入代理、到达核验和去重。
- `navigation_task/patch_task.py`：针对现场 `task.py` 的确定性补丁。
- `navigation_task/patch_frontend.py`、`task_speech_ui.js`：原任务编辑器的语音控件。
- `navigation_task/deploy.py`：分阶段部署和回滚；不启停任何进程。

容器内更新的位置是 `/catkin_ws/src/x_nav_control/scripts/task.py`、同目录新增 `g1_task_voice.py`、`dist/assets/rviz-lv-JGMcm.js` 和 `dist/app/rviz.html`。HTML 的脚本地址包含内容哈希以更新缓存。模块本体保存在版本化发布目录。补丁检查现场源码及锚点；来源变化会中止，不能直接套到其他版本。

`python3 navigation_task/deploy.py stage` 只产生待安装文件与 SHA256 清单。安装前需现场停止任务、导航 Web API 和本模块被动监听进程，并安排受监护的重载；`install` 会检查 Web 端口和监听进程均已停止，备份原文件和任务数据后再替换。不会覆盖地图、阈值、音频配置或机器人程序。回滚使用 `rollback --backup <安装返回的备份目录>`，同样要求相关进程已停止；不会覆盖后来编辑的任务数据。

安装后需重载原导航 Web 进程、使用本发布目录的 `arrival_voice.legacy_auto` 重启被动监听，并刷新原导航页面。**不要通过重启容器或桥接服务代替这个步骤。** 原 `robot_web_controller.py` 启动时会调用 `ProcessManager.auto_run()`，自动启动包括 `/nav/w_nav` 在内的配置进程，因此不能把重载当成纯页面刷新。

音频编辑器仍运行在导航宿主机 `127.0.0.1:18768`，保留现有 SSH 会话和音频服务。任务语音必须在其连接实机时才能成功；模拟后端返回不会当作成功。
