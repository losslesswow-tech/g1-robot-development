# G1 右臂关节调试台

与灵巧手控制台相同，使用数值框、滑条和逐路发送；支持七个右臂关节的三维选择、0.1/0.5/1/2° 微调、实时角度叠加、采用实测值、姿态导入导出。左臂七轴提供只读角度表。

默认页面：<http://127.0.0.1:8771/>。模拟验收页面使用 8772。两个界面均仅绑定本机回环地址，没有向局域网开放控制端口。

## 操作

1. 点击“连接读取”。这只启动 LowState 订阅及状态查询，不发布上肢目标。
2. 点击“采用实测角度”，可比较或保存当前位置。单纯拖动、输入、导入都不下发。
3. 在现场监护、周围清空及手柄停止手段可用的条件下，勾选现场条件。内置手臂服务须停止；如界面显示未停止，可展开设置并点击“关闭内置手臂服务”。该操作仅针对 `g1_arm_example`，不切换整机 FSM。
4. 点击“准备调试”，先从当前实测姿态渐增上肢接管权重。之前编辑的大角度不会自动发送。等状态变为“等待单次发送”。
5. 选择一个关节，输入角度或用 ＋/− 微调，再点击“发送该关节”。只有选中关节的目标改变；移动及到位核对期间拒绝下一条目标。轨迹结束后再核对选中关节实测误差不超过 1°、速度不超过 0.15 rad/s；1.5 秒内未确认则中止，不以经过设定时间代替实际到位。上述容差属于本工具设置，非官方精度保证。
6. 点击“停止调节并交还控制权”，等待“只读 · 未接管”。准备、发送、交还也可在三维视图旁操作。

每次发送的**指令角度变化**最多 20°，右臂每个关节相对本次接管初始目标的范围为 ±50°，仍受官方模型限位约束；接管最长 30 秒。不能连续小步绕过累计范围。滑条完整范围来自官方模型，仅供离线编辑，不能视为已验证的实物范围。准备调试期间，双臂全部受同一接管权重影响；只允许编辑右臂，左臂目标保持接管时姿态。

页面心跳最长间隔 3 秒。断连、切换离开页面、状态失联或保护触发后停止接收新目标，并渐降权重、发送零权重帧。交还过程中不宣称已经只读。故障会保持中止状态，检查现场后显式断开、重新连接，不自动重试。交还仍使用 1.5 秒权重渐降和 0.2 秒零权重帧，不自动规划返回初始姿态，也不保证接收方运控的归位速度为 5°/秒。该机制不是硬件急停，也不证明双脚固定或所有情况下实物回到原位。

## 实物边界

此版本沿用当前 G1 的 `rt/arm_sdk` 接口（domain 0、eno1、HG 消息、PR 模式）；不发布 `rt/lowcmd`，不发送底盘速度、ZeroTorque、StandUp、Start 等整机状态命令。进入调试前要求 FSM 501/mode 0；调试期间主 FSM 必须保持 501，允许 mode 在 0/1 间变化。持续检查机型状态、内置手臂服务停止、单一上肢写入来源、CRC/数值有效与状态新鲜度。

查询返回码与机器人模式值分别保存。进入调试及新目标要求最新查询成功；调试期间单次查询失败不会把模式伪写成 −1，而是暂停轨迹并保持上一目标及权重。每项查询各自从最后一次成功起最多允许 1.5 秒，超过即交还；成功查询报告主 FSM 改变或 mode 不在 0/1 内则立即中止。该期限是本工具设置。故障触发瞬间的返回码、状态值、阶段、权重及传感器读数固定保存在 `fault_context` 和审计日志 `native_fault` 中，后续查询恢复或重新连接不会覆盖审计记录。

2026-10-14 现场点击准备后，查询成功返回 501/1，导致此前仅接受 mode 0 的代码在约 0.06～0.10 秒时交还。该规则已修正。[官方 G1 高层运动服务接口](https://support.unitree.com/home/operator/G1_developer/sport_services_interface) 定义 GetFsmMode 为 0=站立、1=移动；同页 SportModeState 定义其为静态/动态切换许可标记。它不等于主运控 ID 或零力矩状态；上肢 DDS 与内置控制器同时运行。用户已取消必须保持站立的验收条件，因此调试期间的 0↔1 仅显示并记录，不单独中止。不据此推断双脚是否实际迈步，其他躯干检查、腿部电机状态/数据有效性及幅度边界仍保留。

保留工具自定义的躯干倾角/角速度、腿部数据有效性与非零电机状态码、手臂电机标志、右臂 ±50° 实测范围、左臂保持姿态 3° 偏差和跟踪误差检查。腿部速度 0.30 rad/s 改为工具监测参考，超过时显示具体 SDK 关节、速度、连接期峰值，并以 leg_speed_observation 事件记录；不单独中止调节，不猜测更大的替代阈值。该设置不是官方电机故障或已标定安全速度。现场旧版在接管约 0.031 秒、权重约 0.000001668 时因右踝侧摆 SDK11 的 −0.336218 rad/s 触发交还，12 个腿部 motorstate 均为0；随后零权重状态同轴也观察到 −0.544560 rad/s。这些记录不足以判断是否迈步或是否由手臂接管引起。手臂 dq 不用此前未经标定的 0.30 rad/s 阈值中止，遵循用户已要求的只记录读数方式。20° 目标变化的五次轨迹需约 7.5 秒，保持指令峰速 5°/秒；新目标须在 30 秒会话剩余时间内留足轨迹时间及 2 秒到位核对预算，否则拒绝发送。PD 为 kp=60、kd=1.5、tau=0，指令轨迹峰值不高于 5°/s；这些不等于已验证的实物速度或负载范围。

不提供腰部调节。腰部未设置字段在本机固件中的处理仍未完成验证，**该工具不宣称解决此前抬臂引起迈步的问题**。本工具的手动调试范围按用户要求扩大到 ±50°、单次20°；原有独立完整平举/首段复测程序的锁仍保留；头顶、大幅动作、按压、导航及碰撞/接触力控制未接入。

角度使用当前 SDK 读数和官方模型关节顺序，内部 rad、显示 °；模型/实物零位、肩轴及地面未完成标定。姿态文件始终标记为 offline、未标定、未授权执行；导入文件中的执行授权标志无效。

## 运行

服务端为 Python 3.8+ 标准库。界面几何直接复用相邻 `arm-button/web` 的官方模型和 Three.js，无 CDN。Windows 本地启动示例：

```powershell
# 模拟后端，全部数据和发送都仅在内存中演示
python server.py --backend simulation --allow-control --port 8772

# 实物接口：SSH 密钥只以本机文件路径传入，不进入网页、日志或姿态文件
python server.py --backend ssh --ssh-key <已有迁移密钥路径> --allow-control --port 8771
```

`--allow-control` 只开放手动准备按钮，不在启动或连接时接管。省略该选项，HTTP 层拒绝准备调试。页面使用同源检查、独立会话、CSRF 校验、请求去重和单页面控制权；不接受网页传入 SSH 地址、私钥、命令或工作目录。

原生程序独立编译于已核实的迁移容器：Ubuntu 20.04、x86_64、SDK CMake 包 2.0.0。`deploy_native.py` 将源文件和二进制放入现有只读开发挂载，构建并运行 `--self-test`，该自检不初始化 DDS；部署不启动工作进程、不重启已有服务。CMake 物理调节选项默认 OFF，构建调试版本时显式 ON；运行时仍须手动 ACQUIRE。

`runtime.example.json` 记录当前不可变构建路径和 SHA256，不含凭据。通过 SSH 启动的工作进程默认只读，STDIN 指令仅支持 ACQUIRE/SET/PING/RELEASE/QUIT；SET 在原生程序中再次执行右臂索引、20° 步长、±50° 累计范围及模型限位检查。

## 验证

```powershell
python -m unittest discover -s tests -v
node --test tests/test_editor.mjs
```

自动化功能测试全部使用模拟器，不会 ACQUIRE 实物。已完成模拟浏览器流程验证；真机验收只调用连接读取和 QUIT，要求 `command_frames=0`、phase=readonly、读数新鲜。20° 单步与 ±50° 累计范围仅完成软件边界、轨迹速率及只读验证，未由本轮操作执行实物验证。新调试程序的持续接管和其他右臂轴的物理动作尚未验收；此前成功的固定 2° 右肩试动不是此工具全部功能的实物验收。
