## z=0.31 m 结果

- 目标固定 `[0.50, -0.23, 0.31] m`，机器人根部参考坐标，未将它当作离地 1.30 m。
- 两遍均执行：实测姿态接管 2 秒 → DreamControl 默认姿态 2 秒 → `Button_Press_UB` 策略 10 秒 → 返回默认姿态 2 秒 → 退权重并发送零权重帧。
- 第二遍 500 个策略采样、863 帧上肢指令、12 帧零权重（包含初始零权重帧），结束权重 0；结束查询 FSM 501/0。
- 第二遍右肩 pitch 相对起始实测最大转动 59.13°、右肘 79.44°、右腕 roll 66.37°、腰 yaw 15.31°。这些是 DDS 实测值，不是目标角度或仿真值。
- 未出现非零电机状态标志、CRC 拒收或其他上肢指令源。现场确认右臂动作完成、结束后站稳。
- 未控制手指、未接入真实按钮反馈，实体按钮按下成功尚未验证。

## 接口与适配

开发机 `192.0.2.1`，机器人专用接口 eno1 / `192.0.2.2`，DDS domain 0，HG / PR 上肢报文。只发布 `rt/arm_sdk`；下肢保留宇树常规运控，不发布 `rt/lowcmd` 或底盘速度。被动 RTPS 包头检查所见机器人端来源为 `192.0.2.10`。

设备状态客户端/服务端 API 都为 1.0.0.2；动作前核实常规运控 501/0，并按官方要求关闭 `g1_arm_example`（ServiceSwitch 返回 1；后续 ServiceList 确认停止）。第二遍已停止，不重复切换。服务在验证后保持停止，未自动重新启动。

策略仍为固定版本 `ec28b508313d6837de52c68247fbc8cf81fe4935` 的 `Button_Press_UB.pt`，SHA256 `c24af360a2252c372fbf6f1622bec5fdece1f3407838f2597cd2c133adcbceba`。57 维观测、17 维策略输出、0.5 action scale、50 Hz、上下肢关节顺序和 PD 增益沿用作者。前 15 个输出控制腰 yaw 和双臂，最后两个手部输出仅记录，不下发手指命令。

Python 3.10 / PyTorch 2.7.1+cpu 负责策略；既有 Ubuntu 20.04 开发容器中的 SDK2 C++ 适配器负责通信。没有将机器人 SDK 安装进原离线仿真 venv，因此离线入口的无 DDS 环境仍保留。

实测接管时明确填充腰三轴和双臂 17 轴，之后过渡到作者默认姿态。退出不再调用作者会把 `motor_cmd[29].q` 重新写为 1 的 damping 辅助函数；先回默认姿态，再以最新实测姿态退权重，最终明确发送 0 权重帧。

保留模型关节限位、有限数值、低层状态新鲜度、常规运控确认、单一上肢指令源、电机状态标志、select 停止、输入看门狗及单次时限。这些是本适配器的检查，不能冒充官方已标定安全参数。没有应用旧调试台的 20° 单步、±50° 累计、5°/s 或旧躯干/腿部速度阈值。

## 执行边界与记录

`native_transport.cpp` 只有显式 `--live` 才接受 P 指令；`controller.py` 必须显式 `--execute`。`--self-test` 不初始化 DDS，`--observe` 只读。本次 self-test 和 observe 均成功，发送帧为 0，随后才执行各次用户授权的试动。

现场需清空、有人监护并保持手柄可用。select 或接口异常结束本次尝试；正常退出渐退权重，select 中止立即发送零权重。程序的退出机制不等同硬件急停，也不构成任何情况下保持平衡的保证。
