## 坐标与验证边界

0.31 m 是策略输入的机器人参考系相对高度。本模型固定 pelvis 在世界 z=0.753 m，作者仿真入口另外给物体 x 增加 0.03 m，故本次目标方块中心世界坐标为 `[0.53, -0.23, 1.063] m`。它不等于现场按钮离地 1.30 m，也不能用本模型的 pelvis 高度直接标定现场机器人。

模型固定 pelvis，并锁定腰 roll/pitch；它不能验证常规运控下的平衡、迈步或接管反应。左臂和腰 yaw 也参与策略，没有将其当作仅右臂动作。

本封装按真机入口的 0.02 s / 50 Hz 生成观测；上游 MuJoCo YAML 实际 decimation=20、dt=0.002，即 25 Hz。策略轨迹只代表这里明确记录的频率配置。

## 初次离线部署时的源码适配与真机待办

- YAML 手部使用 `_link` 名称，而 XML 关节使用 `_joint`；离线入口只对明确的手部别名转换，按关节名称解析 qpos、qvel 和 actuator，并核验 41 轴一一对应。没有改动手臂顺序。
- 独立定义上肢 15 轴顺序，避免依赖上游 MuJoCo 按钮脚本中未在其基类定义的 `JointNamesOrder_UB`。
- 策略目标由本地配置直接写入观测并逐次核对，避免相机覆盖或上游 7 秒后的目标随机化。没有运行相机或云端识别。
- 原 `common/command_helper.py` 的 `create_damping_cmd()` 在清零后又设置 `motor_cmd[29].q=1`；真机按钮入口在退权重归位后调用它。这是明确的退出报文问题，不能将原脚本退出等同已经交还上肢控制。
- 原真机入口直接切到配置默认姿态，归位操作腰部三轴和双臂；接管、姿态匹配、腰部字段及交还须单独适配并验证。此前准备调试后后倾的根因仍未查明。

初次离线报告中 `hardware_trial_ready=false`，当时没有执行真机按钮任务。后续已单独适配并验证接管、轨迹和交还，详见上方真机记录；离线报告本身仍不代表真机执行许可。
