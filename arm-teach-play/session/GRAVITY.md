# G1 双臂重力与 RH56DFTP 负载补偿

本次适配用于现有 G1 29DoF 的关键点/连续回放。用户已确认双手均为 RH56DFTP，且无额外负载。录制仍使用原有 `tau=0` 的手动支撑低阻尼流程；没有主动悬停或手指联动。

## 模型与计算

使用工作区中已固定并校验 SHA256 的[宇树官方 FTP 集成 URDF](https://github.com/unitreerobotics/unitree_ros/blob/5994d4faef0a9cadd3287f8de0199a67eeb2a259/robots/g1_description/g1_29dof_rev_1_0_with_inspire_hand_FTP.urdf)。只取两臂七轴链接惯性、灵巧手安装变换和手部各链接质量/质心；不叠加本体模型中的 0.170 kg 橡胶假手。

每只手的 URDF 总质量为 **0.8783 kg**。标称手指零位下，等效质心相对腕 yaw 链接为：左 `[0.14540248, -0.00080602, 0.00534790] m`，右 `[0.13795160, 0.00124936, 0.00540762] m`。这是模型汇总值，未替代实物称重；没有凭拟合残差增加额外负载。

原生程序使用实时 HG LowState 的双臂关节角、腰 yaw/roll/pitch 角和骨盆 IMU 四元数 wxyz，转换世界重力向量 `g=[0,0,-9.80665] m/s²` 至 torso 坐标。骨盆/躯干 IMU 区别参考[官方 SDK 示例](https://github.com/unitreerobotics/unitree_sdk2/blob/main/example/g1/low_level/g1_ankle_swing_example.cpp)，其中 LowState 为 pelvis、secondary_imu 为 torso。沿各关节轴计算所有后代质量的重力矩，再取反作为前馈补偿，即 `tau_ff = dU/dq`。

计算在 C++ 原生进程中完成，使用**实测**姿态，不在 Windows 侧通过 SSH 逐帧计算。只给臂 15～28 轴写前馈；腰部前馈与腿部、手指命令保持为零。沿用 `rt/arm_sdk`、HG、domain 0、eno1、PR0、常规运控及原有设备状态 API；没有增加其他控制通道或整机模式切换。

## 有界启用与交还

- 回放连接显式使用 `--gravity`；普通录制连接不使用它。模型校验摘要必须与 runtime 配置一致，才能接受回放。
- 首帧权重 0 且全部前馈力矩为 0；补偿约 2 秒平滑启用，保留原接管权重渐变。由原厂服务向 SDK 控制的实际混合行为仍需现场验证。
- 软件前馈限值采用该 URDF effort 的 60%：肩/肘/腕 roll 各 15 N·m，腕 pitch/yaw 各 3 N·m。这是本工具的保守边界，不是新的厂家额定值或整机安全保证。各轴还限制前馈变化率，前五轴 20 N·m/s、最后两轴 5 N·m/s。
- 非有限姿态、IMU 四元数异常、模型需求超过前馈限值时拒绝接管或停止；不将限幅后的不足补偿报告为正常到位。
- 正常交还时，前馈随权重退至零；Select 等紧急停止路径立即零权重/零前馈。确认最终零权重帧和控制进程退出后，沿用原厂服务恢复规则。
- 位置阈值 2°、到位速度 0.15 rad/s、指令峰速 20°/s、心跳/新鲜度/看门狗、单一写入源、保持及会话期限均保留。

## 验证与边界

数学探针独立于 DDS/SDK，通过完整 URDF 势能的中心差分校验解析重力矩。记录中的所有 2826 帧姿态也做了离线力矩边界核对。生成模型、原生自检、报文零前馈、渐启、限幅、力矩变化率、正常/紧急交还和 Python 会话回归证据位于 `artifacts/g1-arm-teach-play-20261016/`。

手部作为 URDF 标称零位的等效质量点处理，当前没有读取/换算 Modbus 手指反馈。对上次稳态姿态采样的 12 组不同模型手指姿态，补偿差异最大约 0.0545 N·m；这只是采样结果，不是全姿态误差上界。实际手指构型、线缆、质量与安装误差仍会影响结果。

上次失败稳态中，右肩/肘实测估算力矩与模型分别仍有约 2.33 / 1.96 N·m 残差，折算 Kp40 的位置误差约 3.34 / 2.81°。这表明模型补偿能覆盖主要重力项，但不能据离线结果承诺 2° 实机达标；也不能把这些残差直接当作额外手部质量。仍须在现场条件就绪后由用户触发一次回放，检查新增前馈与实测误差，再决定是否需要进一步实物负载标定或受限反馈补偿。

本次部署仅运行离线测试和只读连接，不自动试动、循环或放宽阈值。
